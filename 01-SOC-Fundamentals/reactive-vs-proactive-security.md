# Reactive vs Proactive Security

## 1. Introduction

Security Operations Centres (SOCs) use both reactive and proactive security approaches to protect an organisation's systems, networks, and data.

- **Reactive Security:** Responding to a security incident after it has occurred or been detected.
- **Proactive Security:** Identifying potential threats and addressing security weaknesses before they cause damage.

Both approaches are important for maintaining an organisation's security.

## 2. Reactive Security

Reactive security focuses on responding to security incidents that have already happened or have been detected.

The main objective is to understand the incident, limit its impact, recover affected systems, and prevent similar incidents from happening again.

### Activities under Reactive Security

- **Monitoring:** Continuously monitoring systems, networks, and security events.
- **Detection:** Identifying suspicious or malicious activities and generating alerts.
- **Incident Response:** Taking action when a security incident is detected.
- **Forensic Analysis:** Examining evidence to understand how an incident occurred.
- **Malware Analysis:** Analysing malicious software to understand its behaviour.

### Example

A SOC monitoring tool generates an alert indicating a possible malware infection on an employee's computer.

A SOC analyst investigates the alert, checks whether it is a real incident or a false positive, and escalates or responds according to the organisation's procedures.

The response team may contain the affected device, remove the malware, and restore the system to normal operations.

## 3. Proactive Security

Proactive security focuses on identifying potential threats and addressing security weaknesses before they cause damage.

The main objective is to reduce the possibility of successful attacks by understanding threats and strengthening security defences.

### Activities under Proactive Security

- **Threat Intelligence:** Collecting and analysing information about threats and attacks that may affect an organisation.
- **Threat Hunting:** Searching for hidden threats that may have bypassed existing security tools or defences.
- **Vulnerability Management:** Identifying and fixing weaknesses in systems and devices before attackers can exploit them.

### Example

A threat intelligence report identifies a new attack technique targeting organisations in a particular industry.

The security team reviews the information, identifies potentially affected systems, and strengthens the relevant security defences to reduce the risk of a similar attack.

## 4. Key Differences

| Aspect | Reactive Security | Proactive Security |
|---|---|---|
| Main focus | Responding to detected incidents | Preventing or identifying potential threats early |
| Timing | After an incident occurs or is detected | Before an incident causes damage |
| Objective | Limit damage and restore normal operations | Reduce the likelihood and impact of attacks |
| Activities | Monitoring, detection, incident response, forensic analysis, malware analysis | Threat intelligence, threat hunting, vulnerability management |
| Approach | Response-oriented | Prevention and early-detection-oriented |

## 5. Why Does a SOC Need Both Approaches?

A SOC needs both reactive and proactive security because not every attack can be prevented.

Reactive security helps the organisation respond when an attack occurs, limit its impact, and restore affected systems.

Proactive security helps the organisation understand emerging threats, identify hidden malicious activities, and fix vulnerabilities before attackers exploit them.

Combining both approaches helps an organisation improve its overall security posture.

## 6. Key Takeaway

- **Reactive:** Respond to an attack after it has happened or been detected.
- **Proactive:** Identify and address potential threats before they cause damage.

A SOC uses both approaches to protect organisational assets, respond to security incidents, and reduce future security risks.
